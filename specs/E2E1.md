# Add a standalone end-to-end runner for Postgres -> PGWAL -> publisher destinations

## Summary
Add a standalone runner in `scripts/run_e2e.py` that validates the full path `Postgres -> PGWAL -> WALConsumer worker(s) -> publisher(s) -> destination` without using `pytest` or anything under `tests/`. It will be invoked by one dedicated Make target, while RabbitMQ and Kafka infrastructure remain outside the e2e command and are started separately with the existing per-broker Make targets.

Configuration is split deliberately:
- CLI arguments own execution-shaping options and env file path
- environment variables own connection details, timeouts, and broker naming defaults
- the script reads an env file path from CLI, defaulting to `.local/.env`; process env overrides loaded values

Also add a root `.env.example` documenting the env contract for the e2e flow and existing local broker/database settings.

## Goals
- Add a single-command e2e runner that is fully separate from the `tests/` suite.
- Validate real end-to-end delivery through selected publishers into real destinations.
- Support RabbitMQ and Kafka in one runner, individually or together.
- Support runtime selection of publisher set and consumer worker count from CLI.
- Keep destination infrastructure startup outside the e2e run command.

## Non-Goals
- No `pytest`-based e2e suite under `tests/`.
- No new public library API.
- No broker startup inside the e2e Make target.
- No load-testing or worker-balancing assertions for multi-worker runs.
- No generic plugin/verifier abstraction for future backends in this task.

## Current State
- The repo already has:
  - PostgreSQL logical replication runtime support in `pgwal/`
  - RabbitMQ and Kafka publishers
  - Dockerized Make targets for PostgreSQL, RabbitMQ, and Kafka test infrastructure
  - integration coverage under `tests/` for publisher behavior, but no standalone e2e runner
- `Makefile` starts PostgreSQL, RabbitMQ, and Kafka for the default pytest path.
- `.local/.env` is already included by `Makefile`, but there is no checked-in example env file.

## Required Changes
### 1. Add the standalone runner
Create `scripts/run_e2e.py`.

The script must:
- accept CLI arguments:
  - `--publishers` with comma-separated values `rabbitmq`, `kafka`, or both; required
  - `--consumer-workers` as an integer, default `1`
  - `--env-file` as a path, default `.local/.env`
- load the file from `--env-file` if it exists, using a small stdlib parser
- keep all non-CLI configuration in env variables
- create isolated DB objects and destination names per run
- build one or more `WALConsumer` instances based on `--consumer-workers`
- run `PGWAL` in-process
- perform one deterministic insert
- verify the selected destination(s) receive the message
- exit non-zero on setup, replication, publish, or verification timeout
- never manage Docker or any infrastructure container lifecycle directly

### 2. Consumer worker behavior
For v1:
- `--consumer-workers` defaults to `1`
- each worker gets its own logical replication slot
- all workers may consume from the same filtered test table
- the run succeeds when every selected destination receives at least one valid message from the run
- the script does not need to prove work distribution across workers

### 3. Destination verification
RabbitMQ path:
- use env-provided broker settings
- create a unique exchange, queue, and routing key for the run
- read one message from the queue and assert the payload contains the run marker

Kafka path:
- use env-provided broker settings
- create a unique topic for the run
- read one message from the topic and assert the payload contains the run marker

Shared rules:
- use bounded polling with explicit deadlines
- require all selected destinations to verify in the same run
- treat local publisher handoff without observable destination delivery as failure

### 4. Config contract
CLI-owned options:
- `--publishers`
- `--consumer-workers`
- `--env-file`

Env-owned options:
- PostgreSQL image, db/user/password/port/container values
- RabbitMQ host/port/user/password/vhost
- Kafka host/port
- startup, readiness, and delivery timeouts

Config precedence:
1. CLI arguments for CLI-owned options
2. process environment
3. env file loaded from `--env-file`
4. script defaults

Env file behavior:
- default path is `.local/.env`
- missing env file is not an error
- `.env.example` is documentation-only

### 5. Add Make target and env example
Update `Makefile` with a dedicated `run_e2e` target.

The target must:
- invoke `python scripts/run_e2e.py`
- map Make variables to CLI arguments:
  - `E2E_PUBLISHERS` -> `--publishers`
  - `E2E_CONSUMER_WORKERS` -> `--consumer-workers`
  - `E2E_ENV_FILE` -> `--env-file`
- link PostgreSQL startup/bootstrap as dependencies rather than having the script manage it
- not start RabbitMQ or Kafka

Add `.env.example` at the repo root documenting:
- PostgreSQL settings used by the e2e runner
- RabbitMQ and Kafka broker settings used by the e2e runner
- e2e timeout settings

### 6. Update docs
Update the minimum docs needed to explain:
- `.local/.env` as the default env file
- separate broker startup from e2e execution
- the `run_e2e` usage pattern
- the fact that this flow is separate from the `tests/` suite

Regenerate `docs/project-structure.md` after adding the new files.

## Acceptance Criteria
- `scripts/run_e2e.py` exists and runs independently of `pytest`.
- `make run_e2e` drives the script through CLI parameters.
- RabbitMQ and Kafka can be selected individually or together.
- consumer worker count is configurable from CLI and defaults to `1`.
- the script reads an env file path from CLI and defaults to `.local/.env`.
- `.env.example` documents the env contract with safe defaults only.
- destination infra remains outside the e2e run command.

## Validation
Required validation:
- syntax/import check for `scripts/run_e2e.py`
- `make run_e2e E2E_PUBLISHERS=rabbitmq`
- `make run_e2e E2E_PUBLISHERS=kafka`
- `make run_e2e E2E_PUBLISHERS=rabbitmq,kafka E2E_CONSUMER_WORKERS=2`
- `python scripts/update_project_structure.py`

If broker infrastructure is not running, the expected result is a bounded, clear failure.

## Default Decisions
- Spec filename: `E2E1.md`
- Runner location: `scripts/run_e2e.py`
- Publisher scope: RabbitMQ and Kafka
- Verification strategy: consume from the destination
- Postgres and broker startup ownership: external to the e2e runner
- Default env file path: `.local/.env`
